## 再現手順

スイートの起動と流す先の用意は `2026-10-24-config-op.md` と同じ。
Basic OP に固有なのは次の 3 点。

### 1. クライアントを 2 つ + `client_secret_post` ブロック

```sh
pnpm --filter @u18/auth-worker client:create \
  --client-id <id> --name "<name>" --type confidential \
  --redirect-uri https://localhost.emobix.co.uk:8443/test/a/<ALIAS>/callback
```

設定 JSON には `client` / `client2` に加えて **`client_secret_post` ブロックが要る**。
スイートの `OIDCCServerTestClientSecretPost.java` が専用の設定キーを読み、
「多くのサーバはクライアントごとに認証方式を 1 つに制限するから」と理由を
コメントに書いている。**u18 は 1 クライアントで両方式を受け付ける**ので、
`client` と同じ資格情報を入れてよい。

### 2. ブラウザがやる 3 手を肩代わりする

スイートはブラウザ前提なので、自動で回すには次を代わりに行う。

1. 認可エンドポイントへ遷移し、リダイレクトを辿る
2. **同意画面が出たら hidden フィールドをそのまま `decision=allow` で POST する。**
   値を組み立て直さないこと（`csrf_token` や `code_challenge` を作り直すと
   「画面が出したもの」と違うものを送ることになる）
3. スイートが返す "Processing Implicit Callback" ページが行う
   POST（`text/plain`）を代わりに送る

**cookie は curl に集めさせること**（`-b jar -c jar`）。CSRF は
double-submit cookie（`u18_csrf` / 本番は `__Host-` 付き）なので、
手で組み立てた jar ではセッション Cookie しか入らず、同意の POST が
**403 になる**。これは実装の問題に見えるが、ハーネス側の不備である。

### 3. ログインを通す

未登録アドレスには OTP を送らない（アカウントの有無を漏らさないため）。
**`purpose: "signup"` で始めること。**

`send_email` バインディングがあると OTP はログに出ない。`ConsoleEmailSender`
へ落とすため、`send_email` を外した設定を別名で置いて
`wrangler dev --config <その設定>` で起動する。**`apps/*/wrangler.jsonc` の
glob に当たらない名前にすること**（preflight と本番 dry-run が走査している）。

OTP は wrangler の observability API から取れる。

```sh
curl -s -X POST http://127.0.0.1:<port>/cdn-cgi/local/explorer/api/local/observability/query \
  -H 'Content-Type: application/json' \
  -d '{"sql":"SELECT message FROM logs ORDER BY rowid DESC LIMIT 10"}'
```
