# セキュリティテスト

仕様書 9 / 13 に対応する、攻撃者視点のテストを置く。

Phase 2 以降に追加するもの:

- 認可コードの再利用が必ず失敗すること（同時交換で成功は 1 回だけ）
- Redirect URI の部分一致・サブドメイン・オープンリダイレクトの拒否
- PKCE なし / plain / 不一致な code_verifier の拒否
- ID Token の alg 混同（`none` 等）の拒否
- OTP の総当たりが試行上限で止まること
- WebAuthn の Challenge 再利用とサインカウンター巻き戻りの検出
- アカウント列挙につながる応答差分がないこと

「失敗することを確かめる」テストなので、実装を変えたときに
**静かに通ってしまわない**よう、期待する拒否理由まで検証する。
