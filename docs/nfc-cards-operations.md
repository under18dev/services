# NFC カードの配布と運用

**配る側（運営）が読むもの。** カードを受け取った人向けの案内は
**`https://go.under18.dev/docs`** で配信している（ソースは
`apps/nfc-worker/src/presentation/http/ui/docs-page.tsx`）。

---

## 0. この文書が前提にしていること（#358）

**紐づけコードは無い。** カードをタップした人がログインすれば、その場で
そのカードはその人のものになる。

以前は「タグに書かれていない紐づけコード」を封緘・スクラッチで添える
設計だったが、**ノベルティとして配るものに封緘・再発行のコストが乗る**ため
撤回した（#358、運用者の判断 2026-10-30）。

**その結果、運用上の守りが 1 つだけになった。**

> **配布前のカードを人目に晒さない。**

これは比喩ではなく、**唯一の手当て**である。理由は §2 に書く。

---

## 1. カードを発行する

> **この節は差し替わる（#333）。** 管理ダッシュボード（`/account/admin/nfc`）が
> 入ったら、発行は画面からの操作になる。**ここに書いてあるのは「画面が無い
> 状態での手順」である** —— いま要るので書いてあるが、**長く残す前提で
> 書かれていない。**
>
> 差し替えるときは、この引用ブロックごと消すこと。**残すと、画面があるのに
> API を叩けと言っている文書になる。**

**管理者だけが叩ける。** 画面はまだ無い。いまは API を直接呼ぶ。

```http
POST https://auth.under18.dev/account/nfc/cards
Content-Type: application/json
Origin: https://auth.under18.dev
Cookie: <管理者のセッション>

{ "count": 1, "batch": "bunkasai-2026" }
```

|         |                                                          |
| ------- | -------------------------------------------------------- |
| `count` | 1〜200。**取り消せないので小さく刻む**                   |
| `batch` | 任意。配布の単位。**後からロットごとに止めるときに使う** |

**応答にカード ID が並ぶ。**

```json
{ "cards": [{ "cardId": "nfc_hdt62b396zy809mmqk3v" }] }
```

### タグに焼く値は、これをそのまま URL に入れたもの

```
https://go.under18.dev/c/nfc_hdt62b396zy809mmqk3v
```

> **`go.under18.dev/c/:cardId` を**そのまま**焼かないこと。**
> `:cardId` はコードの中で route を書くときの記法で、**値ではない。**
> 実際に「この URL でいいんですよね？」という確認が来ている（2026-10-30）。
> **コロンもハイフンも入らない。**

**カード ID の形**（`@u18/domain` の `newCardId()`）:

|          |                                                                                        |
| -------- | -------------------------------------------------------------------------------------- |
| 接頭辞   | `nfc_`                                                                                 |
| 長さ     | 接頭辞のあと **20 文字**（全体で 24 文字）                                             |
| 文字集合 | `0123456789abcdefghjkmnpqrstvwxyz`（Crockford base32 から `i l o u` を除いた 32 文字） |

**`i l o u` が無いのは、人が読み書きするときの取り違えを避けるため**（1 と l、0 と o）。
**焼く前に、この形に合っているかを確かめられる:**

```
^https://go\.under18\.dev/c/nfc_[0-9abcdefghjkmnpqrstvwxyz]{20}$
```

**94 がコピペ用の URL 一覧を管理画面に出す**（#382）。それが入れば、ここから組み立てる必要は無くなる。**それまでは応答の `cardId` を上の形に入れること。**

### 管理者の条件

**Passkey で張ったセッションでなければ `isAdmin` が立たない**（仕様書
§14.1 決定 8、RR-5）。メール OTP でログインしただけでは 403 になる。

**`Origin` と `Content-Type: application/json` の両方が要る。**
どちらが欠けても 403（`cards.routes.ts` の門番）。

### 取りこぼしても大丈夫

**応答に秘密は無い。** #358 より前は平文の紐づけコードが載っていて、
取りこぼしたカードは再発行するしかなかった。いまは
`GET /account/nfc/cards` では引けない（あれは自分のカードだけ）が、
**ロットで発行した ID は `batch` から運営が辿れる**。

---

## 2. 配るまでの間が、唯一の危険である

**発行してから誰かが登録するまで、そのカードは「ID を知っている人のもの」
である。**

| 漏れ方                              | 起きること                 |
| ----------------------------------- | -------------------------- |
| 配布前の束を第三者が読む            | **その人が全部登録できる** |
| 発行の応答を画面に出したまま離席    | 同じ                       |
| カード ID を SNS やスライドに載せる | **載せた瞬間に取られる**   |

**総当たりは成立しない。** カード ID は 100 ビット（`newCardId()`）で、
1 万枚・毎秒 1 万回でも最初の 1 枚に当たるまで約 400 兆年。
**守らなければならないのは「当てられること」ではなく「見られること」である。**

### 取られたら

**管理者が付け替えられる。** 取り返しはつく（§4）。
**配布物の印刷は取り返しがつかない** —— #358 でコードを外したのは、
この非対称を見てのことである。

---

## 3. 遷移先が不適切だったとき

**所有者はいつでも遷移先を変えられる。** つまり、配ったあとに何を
入れられるかは運営が決められない。

**止める手段は 2 つある。**

1. **そのカードを無効化する**（§4）—— タップしてもどこへも飛ばなくなる
2. **所有者を付け替える**（§4）—— カードを回収できている場合

**遷移先の一覧を見る画面はまだ無い。** #333 の管理ダッシュボード
（`/account/admin/nfc`）で入る。**それまでは D1 を直接引くしかない。**

書き込める値には制限がある（`domain/services/target-url.ts`）。

- `https:` のみ
- URL 内の資格情報・IP リテラル・イントラネット名・既定以外のポートを拒否
- **IdP 自身のオリジン（`auth.under18.dev`）を拒否** —— 許すと、
  ログイン画面や同意画面を踏ませる導線を外から組み立てられる
- `go.under18.dev` 自身も拒否（リダイレクトの連鎖を作らせない）

**一覧の画面は遷移先をリンクにしていない。** 開いただけで外部へ飛べると、
**その画面が踏み台になる**（カードを奪った側が遷移先を変え、所有者に踏ませる）。

---

## 4. 止める・付け替える

**どちらも所有者本人の操作として作られている。** 運営が代行する経路は
まだ無く、#333 で入る。

### 止める（無効化）

```http
POST https://auth.under18.dev/account/nfc/cards/<cardId>/disable
{ "reason": "lost" }      # lost | unused
```

**片道である。所有者は自分で戻せない。** 戻すのは運営の操作にしてある ——
拾った人間に「このカードは止められている」と教えないため。

**次のタップから効く。** 302 に `Cache-Control: no-store` を付けてあるので、
一度タップした端末も毎回問い合わせに来る。

**止めたカードは「存在しないカード」と 1 バイトも変わらない応答になる。**
これは紛失対策の本体である。

### 付け替える（手放す → 次の人が登録）

```http
POST https://auth.under18.dev/account/nfc/cards/<cardId>/release
```

カードは未登録の状態へ戻り、**遷移先も消える。**

> **手放した瞬間から、そのカードは次にタップした人のものになる。**

**手放すのは相手に渡す直前にすること。** #358 より前は新しい紐づけコードが
1 度だけ返り、それを渡すまでは誰も登録できなかった。**いまその保護は無い。**

---

## 5. 運用で触ってはいけないもの

|                                          | 理由                                                                        |
| ---------------------------------------- | --------------------------------------------------------------------------- |
| `go.under18.dev/c/:cardId` の URL の形   | カードに印字・書き込み済みで、**後から変えられない**                        |
| 302 を 301 にする                        | 端末が対応付けを**無期限にキャッシュ**し、無効化が効かなくなる              |
| `Referrer-Policy: no-referrer` を外す    | 遷移先にカード ID が渡る。**#358 以降、それは未登録カードを渡すことに近い** |
| 無効化済みと「存在しない」の応答を分ける | 拾った人間に手掛かりを与える                                                |

**`issued`（未登録）だけが外から区別できる。** タップした人を登録の画面へ
送るためで、**漏れるのは「この ID は実在し、まだ誰のものでもない」の 1 ビット**
である。何を区別して何を区別しないかは
`apps/nfc-worker/src/domain/services/disclosure.ts` が 1 箇所で決めている。

---

## 6. D1 を直接触るとき

**`u18-nfc` は Identity とは別の D1 である。** nfc-worker は Identity D1 の
binding を持たない（仕様書 2.2 / 4.1）。

**手で SQL を書かないこと。** 列の組み合わせを間違えると、
**所有者が残ったまま未登録のカード**のような、どの経路からも扱えない行が
できる（`Card.isClaimable()` は状態と所有者の両方を見る）。

**未登録へ差し戻すときは、カードを回収できている場合に限る。**
回収していないのに戻すと、**そのカードを持っている人がタップするだけで
自分のものにできる。** 詳しい手順は `docs/runbook.md` §11.2 / §12.4。
