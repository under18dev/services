# NFC カードの配布と運用

**配る側（運営）が読むもの。** カードを受け取った人向けの案内は
**`https://go.under18.dev/docs`** で配信している（ソースは
`apps/nfc-worker/src/presentation/http/ui/docs-page.tsx`）。

---

## 0. この文書が前提にしていること（#358）

**紐づけコードは無い。** カードをタップした人がログインすれば、その場で
そのカードはその人のものになる。

以前は「タグに書かれていない紐づけコード」を封緘・スクラッチで添える
設計だったが、**ノベルティとして配るものに封緘・再発行のコストが乗る**ため
撤回した（#358、運用者の判断 2026-10-30）。

**その結果、運用上の守りが 1 つだけになった。**

> **配布前のカードを人目に晒さない。**

これは比喩ではなく、**唯一の手当て**である。理由は §2 に書く。

## 1. カードを発行する

> **この節は #382 で差し替わった。** 以前はここに「管理ダッシュボードが入ったら
> 画面からの操作になる」と書いてあったが、**差し替え先は画面ではなく
> スクリプトになった** —— 運用者が必要としていたのは「web から押せること」
> ではなく「**1 枚ずつ違う URL を手でコピペしなくて済むこと**」だった。
>
> **発行と書き込みを 1 本のスクリプトで通す。** 下の「手で発行する」は、
> スクリプトが使えない環境のための退路として残してある。

## 1-1. タグへ焼く

> **本体は `scripts/nfc-burn.py`。** ただし **読み取り機（Sony PaSoRi
> RC-S300）から Python で書けるかは、まだ実機で確かめられていない。**
> そこが通らないと本体も動かないので、**先に `scripts/nfc-spike.py --write`
> を通すこと。**

```bash
pip install pyscard

# 読むだけ（タグを書き換えない）
python3 scripts/nfc-spike.py

# 書き込みまで試す。**タグを書き換えるので、配布に使わない 1 枚で**
python3 scripts/nfc-spike.py --write
```

**4 段を順に確かめ、落ちた段の生の APDU と応答をそのまま出す。**

|       |                                  |
| ----- | -------------------------------- |
| ①     | pyscard が読み取り機を見つけるか |
| ②     | NTAG215 を読めるか               |
| **③** | **NDEF を書けるか** ← ここが本番 |
| ④     | 読み戻して一致するか             |

### 何が確定していて、何が未確定か

**確定**: RC-S300 が運用者の macOS で動き、**NFC Tools（デスクトップ版）から
NTAG215 に NDEF を書けている。**

**未確定**: **`pyscard` から同じことができるか。** NFC Tools が PC/SC を
使っているなら `pyscard` と同じ層なので見込みはあるが、**確かめていない。**
**①で読み取り機が見つからなければ、NFC Tools は別経路を使っている**ことに
なるので、そこで止めて報告すること。

**既に NFC Tools で焼いたタグがあれば、②でそれを読むのが早い** ——
自分で書く前に、読めることだけ先に確かめられる。

### 焼くバイト列は確認済み

**ここだけはハードウェア無しで確かめられる**（`scripts/nfc_ndef.py`）。

```bash
python3 scripts/nfc_ndef.py        # 自己検査
```

```
URL  https://go.under18.dev/c/nfc_hdt62b396zy809mmqk3v   49 バイト
TLV  03 2e d1 01 2a 55 04 67 6f ... fe                   49 バイト
```

`https://` を URI レコードの接頭辞コード `0x04` に畳むので、**49 バイトの
URL が TLV 全体 49 バイトに収まる。** NTAG215 のユーザ領域は 504 バイトで、
**455 バイト余る。**

### 本体（`scripts/nfc-burn.py`）の動き

運用者の指定:

> 60 枚ですがこれからも使っていきたいので、while で都度 id 作って
> ctrl+c で停止みたいにしたく

```
while:
    ① タグが載るのを待つ
    ② 既に書き込まれていないか見る     既にあればスキップ（--force で上書き）
    ③ API でカードを 1 枚発行           ← タグが目の前にあってから
    ④ NDEF を書く
    ⑤ 読み戻して確かめる
    ⑥ タグが外れるのを待って次へ
Ctrl+C → 焼いた枚数・最後の Card ID・**焼けなかった Card ID** を出して終わる
```

**①→③ の順序が肝心である。** まとめて発行してから焼くと、Ctrl+C のたびに
**発行済みで焼かれていないカード（孤児）**が残る —— `issued` のまま一覧に
並び続け、**対応する物理タグがどこにも無い。**

**③ と ④ の間で落ちたときだけ孤児が出る。** 避けられないので、**その
Card ID をはっきり出して止まる**（黙って次へ行かない）。

**既に書き込まれているタグを既定で上書きしない。** 上書きすると前のカードが
孤児になり、**そのタグを持っている人がいたら、その人のカードが死ぬ。**

## 1-1-1. 60 枚焼く

**セッションを渡す。** 管理者の Cookie を環境変数から読む。**`export` の前に
空白を 1 つ置く**と履歴に残らない（bash なら `HISTCONTROL=ignorespace`、
zsh なら `setopt histignorespace`）。

```bash
 export U18_SESSION_COOKIE='__Host-u18_session=...'   # ← 行頭に空白
```

| 取り方 |                                                                                                       |
| ------ | ----------------------------------------------------------------------------------------------------- |
| 1      | `https://auth.under18.dev` に **Passkey で**ログインする（§1-2「管理者の条件」。OTP では 403 になる） |
| 2      | DevTools → Application（Firefox は Storage）→ Cookies → `https://auth.under18.dev`                    |
| 3      | `__Host-u18_session` の **Name と Value を `=` で繋いで**環境変数へ                                   |

**通ることを先に確かめる。** どちらもタグには書かない。

```bash
python3 scripts/nfc-burn.py --self-test   # 組み立てと読み戻しの往復
python3 scripts/nfc-burn.py --dry-run     # 焼く URL と APDU を出す。API は叩かない
```

**セッションと権限まで確かめたいとき**は `--dry-run --live-issue`。
**本物のカードが 1 枚出る**（= 孤児が 1 枚増える）ので、出た Card ID を
控えて §1-1-3 の手順で無効化すること。

**焼く。**

```bash
python3 scripts/nfc-burn.py --batch bunkasai-2026 --count 60
```

|                |                                                                       |
| -------------- | --------------------------------------------------------------------- |
| `--batch`      | **付けること。** 無いと後から配布の単位で辿れない（§1-2）             |
| `--count 60`   | 60 枚で止まる。付けなければ Ctrl+C まで回り続ける                     |
| `--log <path>` | 焼いたものを TSV に追記する。**0600 で作る**（中身は Card ID の一覧） |
| `--force`      | **書き込み済みのタグも上書きする。** §1-1-4 を読んでから              |
| `--verbose`    | 通った APDU も全部出す。うまく行かないときに                          |

**1 枚ずつ。タグを載せる → 焼ける → 外す → 次を載せる。** 1 枚あたり 1 行で、
`OK` のあとに焼いた URL が出る。**`OK` が出たカードは読み戻しまで通っている。**

```
[12/60] タグを載せてください… (Ctrl+C で終了)
    OK  https://go.under18.dev/c/nfc_hdt62b396zy809mmqk3v
    タグを外してください…
```

## 1-1-2. 止めたあとの再開

**Ctrl+C はいつ押してもよい。** 押すとその場で止まり、

- 焼けた枚数
- 最後に焼いた Card ID と URL
- 飛ばした枚数
- **発行済みで焼けなかった Card ID**（あれば。§1-1-3）

が出る。**再開は同じコマンドをもう一度打つだけ。** 途中の状態はどこにも
持っていない —— **1 周が 1 枚で完結している**ので、「続き」という概念が無い。

**`--count` は「この実行で焼く枚数」である。** 20 枚焼いたところで止めたなら、
次は `--count 40`。**合計を数えているのはスクリプトではなく人間である。**
`--log` を同じファイルに向けておけば、そこの行数が通算になる。

**同じ `--batch` を使い続けてよい。** ロット名は発行時のラベルで、重複して
困るものではない。

## 1-1-3. 焼けなかったカードの始末

**書き込みの途中で落ちると、発行済みのカードが 1 枚浮く。** D1 には `issued`
のまま残り、**対応する物理タグがどこにも無い。** スクリプトはそこで**止まり**、
その Card ID を出す。

```
** 発行済みだが焼けていないカード（孤児） **
   D1 に `issued` のまま残ります。**対応する物理タグはありません。**
   - nfc_hdt62b396zy809mmqk3v    ページ 0x08 に … を書けません（SW=6300）
```

**放置しない。** 未紐づけのカードは **ID を知っている人がタップすればその人の
ものになる**（§2）。画面の一覧にも「未紐づけ」として並び続けるので、どれが
実在するタグなのか分からなくなる。

**無効化する。** `admin.under18.dev/nfc` の一覧から、または:

```http
POST https://auth.under18.dev/account/nfc/cards/<cardId>/disable
{ "reason": "unused" }
```

`"lost"` ではなく **`"unused"`** を使う —— 紛失したのではなく、**最初から
誰の手にも渡っていない。**

**中途半端に書かれたタグは、もう一度流せばよい。** ただし NDEF の頭
（`03`）が残っていると ② の「既に書き込みがある」で飛ばされる。**その
ときだけ `--force`** —— §1-1-4 を読むこと。

## 1-1-4. `--force` を使う前に

**既定では、書き込み済みのタグを飛ばす。** 上書きすると、**そのタグに載って
いたカードが孤児になる。** そのカードを既に誰かが持っていたら、**その人の
カードは次のタップから別物になる。**

**使ってよいのは、そのタグが誰にも渡っていないと言い切れるときだけ。**
試し書きしたタグ、焼いたが配らなかったタグ、`nfc-spike.py --write` を試した
タグ。**配った可能性が少しでもあるなら使わない。**

**上書きする前に、元の書き込みが画面に出る。** 見覚えのない URL が出たら
止めること。

## 1-2. 手で発行する（退路）

**スクリプトが使えない環境のため。** ブラウザの開発者コンソールか `curl` で。

**管理者だけが叩ける。** `scripts/nfc-burn.py` が叩いているのもこの経路である。

> **この経路は #390 の段取り 5 / 6 で消える。** 管理画面は #412 で
> `admin.under18.dev/nfc` へ移っており、#390 は「移したら消す」と書いている。
> **消えたときに何を決め直すことになるか**は `scripts/nfc-burn.py` の
> docstring にまとめてある（`admin.under18.dev/nfc` は HTML フォームで、
> **発行しても Card ID が応答に返らない**）。

```http
POST https://auth.under18.dev/account/nfc/cards
Content-Type: application/json
Origin: https://auth.under18.dev
Cookie: <管理者のセッション>

{ "count": 1, "batch": "bunkasai-2026" }
```

|         |                                                          |
| ------- | -------------------------------------------------------- |
| `count` | 1〜200。**取り消せないので小さく刻む**                   |
| `batch` | 任意。配布の単位。**後からロットごとに止めるときに使う** |

**応答にカード ID が並ぶ。**

```json
{ "cards": [{ "cardId": "nfc_hdt62b396zy809mmqk3v" }] }
```

### タグに焼く値は、これをそのまま URL に入れたもの

```
https://go.under18.dev/c/nfc_hdt62b396zy809mmqk3v
```

> **`go.under18.dev/c/:cardId` を**そのまま**焼かないこと。**
> `:cardId` はコードの中で route を書くときの記法で、**値ではない。**
> 実際に「この URL でいいんですよね？」という確認が来ている（2026-10-30）。
> **コロンもハイフンも入らない。**

**カード ID の形**（`@u18/domain` の `newCardId()`）:

|          |                                                                                        |
| -------- | -------------------------------------------------------------------------------------- |
| 接頭辞   | `nfc_`                                                                                 |
| 長さ     | 接頭辞のあと **20 文字**（全体で 24 文字）                                             |
| 文字集合 | `0123456789abcdefghjkmnpqrstvwxyz`（Crockford base32 から `i l o u` を除いた 32 文字） |

**`i l o u` が無いのは、人が読み書きするときの取り違えを避けるため**（1 と l、0 と o）。
**焼く前に、この形に合っているかを確かめられる:**

```
^https://go\.under18\.dev/c/nfc_[0-9abcdefghjkmnpqrstvwxyz]{20}$
```

**焼く URL の一覧は、管理画面（`/account/nfc/admin`）にも出ている**（#377）—— **未紐づけのカードだけ**が 1 行 1 枚で並ぶ。手で焼くならそこからコピーする。**スクリプトを使うなら、一覧を見る必要も無い**（発行と書き込みが繋がっているので）。

### 管理者の条件

**Passkey で張ったセッションでなければ `isAdmin` が立たない**（仕様書
§14.1 決定 8、RR-5）。メール OTP でログインしただけでは 403 になる。

**`Origin` と `Content-Type: application/json` の両方が要る。**
どちらが欠けても 403（`cards.routes.ts` の門番）。

### 取りこぼしても大丈夫

**応答に秘密は無い。** #358 より前は平文の紐づけコードが載っていて、
取りこぼしたカードは再発行するしかなかった。いまは
`GET /account/nfc/cards` では引けない（あれは自分のカードだけ）が、
**ロットで発行した ID は `batch` から運営が辿れる**。

## 2. 配るまでの間が、唯一の危険である

**発行してから誰かが登録するまで、そのカードは「ID を知っている人のもの」
である。**

| 漏れ方                              | 起きること                 |
| ----------------------------------- | -------------------------- |
| 配布前の束を第三者が読む            | **その人が全部登録できる** |
| 発行の応答を画面に出したまま離席    | 同じ                       |
| カード ID を SNS やスライドに載せる | **載せた瞬間に取られる**   |

**総当たりは成立しない。** カード ID は 100 ビット（`newCardId()`）で、
1 万枚・毎秒 1 万回でも最初の 1 枚に当たるまで約 400 兆年。
**守らなければならないのは「当てられること」ではなく「見られること」である。**

### 取られたら

**管理者が付け替えられる。** 取り返しはつく（§4）。
**配布物の印刷は取り返しがつかない** —— #358 でコードを外したのは、
この非対称を見てのことである。

## 3. 遷移先が不適切だったとき

**所有者はいつでも遷移先を変えられる。** つまり、配ったあとに何を
入れられるかは運営が決められない。

**止める手段は 2 つある。**

1. **そのカードを無効化する**（§4）—— タップしてもどこへも飛ばなくなる
2. **所有者を付け替える**（§4）—— カードを回収できている場合

**一覧は管理画面にある**（`admin.under18.dev/nfc`、#412）—— 全部のカードの
所有状況・状態・遷移先が見える。**遷移先は意図的にリンクにしていない** ——
開いただけで外部へ飛べると、**確認しに来た運営がその場で踏む**ことになる。

**同じ画面から直せる。** 他人のカードの遷移先の変更・無効化・所有者の
手放させ（付け替えではない、§4 を参照）は、`NfcAdminDelegatedRPC` 経由で
運営が行える（#382 / #412 / #422）。D1 を直接引く必要は無い。

書き込める値には制限がある（`domain/services/target-url.ts`）。

- `https:` のみ
- URL 内の資格情報・IP リテラル・イントラネット名・既定以外のポートを拒否
- **IdP 自身のオリジン（`auth.under18.dev`）を拒否** —— 許すと、
  ログイン画面や同意画面を踏ませる導線を外から組み立てられる
- `go.under18.dev` 自身も拒否（リダイレクトの連鎖を作らせない）

**一覧の画面は遷移先をリンクにしていない。** 開いただけで外部へ飛べると、
**その画面が踏み台になる**（カードを奪った側が遷移先を変え、所有者に踏ませる）。

## 4. 止める・付け替える

**止める・遷移先の変更・一覧・発行・手放させるは、運営が代行できる**
（`NfcAdminDelegatedRPC` —— `disableCard` / `updateCardTarget` /
`listAllCards` / `issueCards` / `releaseCard`、置き場所は
`admin.under18.dev/nfc`）。

### 止める（無効化）

```http
POST https://auth.under18.dev/account/nfc/cards/<cardId>/disable
{ "reason": "lost" }      # lost | unused
```

**片道である。所有者は自分で戻せない。** 戻すのは運営の操作にしてある ——
拾った人間に「このカードは止められている」と教えないため。

**次のタップから効く。** 302 に `Cache-Control: no-store` を付けてあるので、
一度タップした端末も毎回問い合わせに来る。

**止めたカードは「存在しないカード」と 1 バイトも変わらない応答になる。**
これは紛失対策の本体である。

### 付け替える（手放す → 次の人が登録）

```http
POST https://auth.under18.dev/account/nfc/cards/<cardId>/release
```

カードは未登録の状態へ戻り、**遷移先も消える。**

> **手放した瞬間から、そのカードは次にタップした人のものになる。**

**手放すのは相手に渡す直前にすること。** #358 より前は新しい紐づけコードが
1 度だけ返り、それを渡すまでは誰も登録できなかった。**いまその保護は無い。**

### 運営が代わりに手放させる（#422）

```
admin.under18.dev/nfc の「手放させる」
```

**連絡が取れない相手にカードを渡したままの状態や、渡す前に別の人へ
タップされてしまった場合に使う。** 結果は本人が `release` したときと
同じ——未登録（`issued`）へ戻り、遷移先も消える。

**「付け替える」ではない。** 運営が直接別の利用者へ束縛する手段は
意図的に作っていない——`NfcAdminDelegatedRPC` の `releaseCard` は
手放すだけで、次の持ち主は必ずタップして自分で登録する。カードの
セキュリティモデルは「タップ＝物理的占有の証明」であり、運営がそれを
迂回できる形にすると、admin-worker の権限が悪用・侵害されたときに
「誰のカードでも別人のものにできる」という攻撃面が増える。

**実行前に、必ず本人へ連絡すること。** 止める（無効化）と違い、この操作は
**本人の画面からカードが消える。** 本人には「無効化された」とも「自分で
手放した」とも見えない、説明の付かない消え方をする——機械では守れないので、
運用者の手順として徹底する。

## 5. 運用で触ってはいけないもの

|                                          | 理由                                                                        |
| ---------------------------------------- | --------------------------------------------------------------------------- |
| `go.under18.dev/c/:cardId` の URL の形   | カードに印字・書き込み済みで、**後から変えられない**                        |
| 302 を 301 にする                        | 端末が対応付けを**無期限にキャッシュ**し、無効化が効かなくなる              |
| `Referrer-Policy: no-referrer` を外す    | 遷移先にカード ID が渡る。**#358 以降、それは未登録カードを渡すことに近い** |
| 無効化済みと「存在しない」の応答を分ける | 拾った人間に手掛かりを与える                                                |

**`issued`（未登録）だけが外から区別できる。** タップした人を登録の画面へ
送るためで、**漏れるのは「この ID は実在し、まだ誰のものでもない」の 1 ビット**
である。何を区別して何を区別しないかは
`apps/nfc-worker/src/domain/services/disclosure.ts` が 1 箇所で決めている。

## 6. D1 を直接触るとき

**`u18-nfc` は Identity とは別の D1 である。** nfc-worker は Identity D1 の
binding を持たない（仕様書 2.2 / 4.1）。

**手で SQL を書かないこと。** 列の組み合わせを間違えると、
**所有者が残ったまま未登録のカード**のような、どの経路からも扱えない行が
できる（`Card.isClaimable()` は状態と所有者の両方を見る）。

**未登録へ差し戻すときは、カードを回収できている場合に限る。**
回収していないのに戻すと、**そのカードを持っている人がタップするだけで
自分のものにできる。** 詳しい手順は `docs/runbook.md` §11.2 / §12.4。
