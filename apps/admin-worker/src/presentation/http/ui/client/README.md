# admin-island の `data-*` 契約（#470）

`admin-island.ts` は 1 本だけ。`/audit` `/clients` `/nfc/analytics`（この
issue）に続き、`/nfc` `/users` `/user-detail` `/approvals`（#471〜#473）も
同じスクリプトを読み込んで、自分の HTML に以下の属性を付けるだけで動く。
**共有コンポーネントにはしていない**——作ると全員が同じファイルを触って
衝突する。属性の形だけがここでの契約である。

属性の形を変えたら、**ここを直してから push すること。** 他のセッションは
この表だけを見て自分の画面を作る。

## 並べ替え

```html
<table data-sortable>
  <thead>
    <tr>
      <th data-sort="text">名前</th>
      <th data-sort="number">件数</th>
      <th data-sort="date">更新</th>
    </tr>
  </thead>
  <tbody>
    ...
  </tbody>
</table>
```

`<th data-sort>` の中身をボタンに差し替える。クリックで昇順 → 降順を
トグル。並べ替えるのは `tbody > tr` の並びだけで、サーバーが決めた既定順
（= JS 無しのときに見える順）はそのまま残る。

`kind` は `text` / `number`（桁区切りのカンマは無視）/ `date`
（`Date.parse` で読めるもの）。

## 絞り込み

```html
<input data-filter="<table か ul の id>" hidden placeholder="この一覧から絞り込み" />
```

**叩き台（`<table の id>` 限定）から変えてある。** `/clients` の一覧が
`<table>` ではなく `<ul>` なので、`id` を持つ `<table>` にも `<ul>` にも
使えるようにした。対象の直接の子（`<table>` なら `tbody > tr`、`<ul>` なら
`:scope > li`）を、見えているテキストで部分一致フィルタする。

**文言に「検索」を使わないこと。** サーバー側に `/users/search` のような
本物の検索・ページングがある画面では、「検索」と書くと**いま見えていない
行（2 ページ目など）まで検索したように読める。** ここが見るのは**いま
画面に出ている分だけ**なので、「この一覧から絞り込み」のように、対象が
現在表示中の範囲であることが伝わる文言にする。

**件数は自動で付く。** `input` の直後に「N 件」または「N / 全 M 件
（この一覧から絞り込み）」という `<p>` を足す——絞り込みで行を隠した
ぶん、ページのどこかにある「全 N 件」のような数が古いまま残って嘘になる
のを防ぐため（指摘: 3b）。ページ側が別の場所に総数を出していて、そちらも
生きた数にしたい場合は `data-filter-count="<同じ id>"` を持つ要素を
置けば、絞り込み後の件数がその要素の `textContent` へも書かれる。

## コピー

```html
<button data-copy="<コピーする文字列>" hidden>コピー</button>
```

クリックで `navigator.clipboard.writeText()`。失敗した場合（API が無い・
許可されない）はボタンの文言が「コピーできません（選択してコピーして
ください）」に変わる——失敗を黙って握りつぶさない。

## タブ

```html
<div data-tabs>
  <button data-tab="a">A</button>
  <button data-tab="b">B</button>
  <section data-panel="a">...</section>
  <section data-panel="b">...</section>
</div>
```

**この issue の 3 画面では使っていない。** #454 の解析 6 区画を縦一列の
ままにする、という明示の判断のため（利用者は「解析はガッチガチに見た
い」と言っており、半分をタブの裏へ隠すのは逆行する）。それでも契約として
渡す以上、未使用のまま置かない——挙動は `admin-island.test.ts` で、見本は
`preview:html` の `tabs-sample.html`（架空データ）で確かめられる。

JS が無ければ `<section>` は誰にも隠されず、見出し付きで縦に並ぶ
（絶対条件）。JS がある場合は既定で 1 枚目の `data-panel` だけが見える。
`data-tab` に対応する `data-panel` が無くても、クリックしても落ちない。

## 吹き出し

```html
<rect data-tip="2026-11-01 · 12 タップ"></rect>
```

ホバー/フォーカスで、対応するカード（Kiwa の色トークンに合わせた小さな
枠）を出す。ブラウザ既定の `title` ツールチップは使わない——見た目を
選べず、運用者から「デザインに AI 味が強い」と言われている画面だから。

いまは `/nfc/analytics` のグラフの `<rect>` にしか付けていない。
`tabindex="0"` を自動で足すので、マウスが無くても辿れる。

## 通知

```html
<p data-notice>保存しました。</p>
```

**叩き台（「既存の `?notice=` をトーストに」）から変えてある。** `/users`
のように `?notice=suspended` のようなコードを URL へ積む画面は、サーバー
側で既に人の読む文へ変換している。JS 側で `?notice=` を読んでコードから
文を組み直すと、**同じ文言がサーバーと JS の 2 箇所に分かれ**、片方だけ
直る事故が起きる（指摘: 3b）。

代わりに、**サーバーが描いた人の読む文そのもの**に `data-notice` を付ける
——リダイレクト経由でもその場描画でも、どちらの経路で出した文でも同じ
属性で拾える。JS はその要素を見つけたら、同じ文でトーストを足す。
**要素自体は消さない。** トーストが数秒で消えても、本文には同じ文が残る
（絶対条件）。

## 共通の絶対条件

- JS が無くても全画面が読める。上の属性はすべて**後付けの便利さ**で、
  前提にしない。
- インライン `<script>` も `onclick` も使わない（CSP: `script-src
'self'`）。
- `hidden` で描いた要素（絞り込み欄・コピーボタン）は、対応する
  `attach*` が呼ばれたときに JS が外す。呼ばれなければ `hidden` のまま
  —— 壊れたページではなく、「JS 無しの絞り込み欄」が無いだけの状態になる。
